# ブランチ名生成スキル

ユーザーから入力された要件やプロジェクト内の仕様に基づいて、Gitのブランチ名を生成するスキルです。ブランチ名はプロジェクトの規約や目的に応じて適切な命名規則を使用して生成されます。以下のガイドラインに従って、ブランチ名を作成してください。


## 1. 基本的な命名規則（ルール）
-   **すべて小文字、単語間はハイフン（`-`）で繋ぐ（ケバブケース）**
    -   `feat/add-login-function` 〇
    -   `feat/AddLoginFunction` ✕（大文字小文字の区別でトラブルが起きやすい）
    -   `feat/add_login_function` ✕（スネークケースはURLやCLIで少し扱いづらい場合がある）
-   **英数字とハイフン、スラッシュ（`/`）のみを使用する**
    -   日本語（全角文字）やスペース、特殊文字（`?`, `*`, `.` など）は、Gitのコマンドや外部ツールで予期せぬエラーの原因になるため避けます。

## 2. 最も一般的な構成（プレフィックスの活用）
ブランチの目的に応じて「プレフィックス（接頭辞）/ 概要」という形式にするのが現在の主流です。スラッシュを入れることで、SourceTree などのGUIツールやCLIでグループ分け（フォルダ分け）されて見やすくなります。

| プレフィックス | 用途 | 具体的ケース |
| --- | --- | --- |
| `feat/` | 新機能の開発 | `feat/user-profile-page` |
| `fix/` | バグの修正 | `fix/payment-button-error` |
| `hotfix/` | 本番環境の緊急バグ修正 | `hotfix/session-leak` |
| `docs/` | ドキュメントの作成・修正（READMEなど） | `docs/api-specification` |
| `style/` | コードの意味に変更を加えない修正（フォーマット、空白など） | `style/eslint-formatting` |
| `refactor/` | リファクタリング（機能追加やバグ修正を含まないコード整理） | `refactor/optimize-db-query` |
| `chore/` | ビルドプロセスやツール、ライブラリのアップデートなど雑多な作業 | `chore/update-dependencies` |

## 3. 仕様駆動開発（SDD）フレームワーク利用時の対応
プロジェクト内で **Spec Kit** やその他の**仕様駆動開発フレームワーク**が使用されている場合は、ブランチ名の生成前に以下の規約・仕様書を確認してください。

- **Spec Kit (`spec-kit`)**: `.specify/` や `specs/<NNN-feature-name>/` が存在する場合、Spec Kit のフィーチャーディレクトリと紐づく命名規則（例: `001-user-profile-page` のような連番付きフィーチャー名）や `.specify/memory/constitution.md` の規約を確認し、整合するブランチ名を提案します。
- **Kiro / `cc-sdd`**: `.kiro/` が存在する場合、`.kiro/steering/`（`structure.md` や `tech.md`）に定められたブランチ規約や、`.kiro/specs/<機能名>/`（`requirements.md`）の機能名を確認します。
- **OpenSpec**: `openspec/` が存在する場合、`openspec/changes/<変更提案ID>/`（`proposal.md`）や `openspec/specs/` の名称・規約を確認します。
- **その他のフレームワーク / 一般的な仕様書**: フレームワーク固有の規約ファイルや `SPEC.md`、`docs/spec.md` 等が存在する場合は、記載されている機能名やプロジェクト規約を参照します。

※ フレームワークやプロジェクト固有のブランチ命名規則が定義されている場合は、上記の汎用プレフィックス構成よりも**フレームワーク・プロジェクト側の規約を優先**してください。

## 手順
1. プロジェクト内に仕様駆動開発フレームワーク（Spec Kit、Kiro / `cc-sdd`、OpenSpec など）や仕様書が存在するか確認し、ユーザーからブランチの目的や対象機能・内容を聞き取ります。
2. フレームワーク固有の規約がある場合はそれに従い、ない場合は上記の基本的な命名規則とプレフィックスのガイドラインに従って、適切なブランチ名を生成してください。
3. 生成したブランチ名をユーザーに提示し、必要に応じて修正の提案を行ってください。
4. 最終的なブランチ名が決定したら、`git checkout -b 生成したブランチ名` を実行するかどうか、ユーザーに確認してください。
5. ユーザーに確認する方法は、ブランチ名が複数ある場合は選択肢を提示して選んでもらう方法で、ブランチ名がひとつしかない場合は、ブランチを作成するかどうか選択させる方法でお願いします。
