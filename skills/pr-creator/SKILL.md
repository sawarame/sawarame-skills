# プルリクエスト作成スキル (`pr-creator`)

現在の作業ブランチの変更内容（コミット履歴および差分）を読み取り、必要に応じてコミットおよびリモートへのプッシュを行ったうえで、**ユーザーへの事前確認を挟まずに**通常のプルリクエスト（Pull Request）を作成するスキルです。

---

## 実行手順

以下のステップを順番に実行してください。

### 1. 現在のブランチ確認（セーフティチェック）
1. `git branch --show-current` を実行して現在のブランチ名を取得します。
2. **中断条件**:
   - 現在のブランチが `main` または `master` の場合は、処理を**即座に中断**し、「`main` / `master` ブランチ上では PR を作成できないため中断しました」とユーザーに報告して終了してください。
   - detached HEAD 状態などでブランチ名が取得できない場合も、同様に中断して報告してください。
3. すでに現在のブランチからオープンな PR が存在しないかを確認します（例: `gh pr view --json url,state,baseRefName`）。
   - すでにオープンな PR が存在する場合は、後続のコミット／プッシュのみ必要であれば実施し、新規 PR は重複作成せず既存 PR の URL を報告して終了してください。

### 2. 未コミット変更の確認とコミット（`commit-message-generator` の利用）
1. `git status --porcelain` を実行し、未コミットの変更（ステージ済み・未ステージ・未追跡ファイル）があるか確認します。
2. **すべての変更がコミット済みの場合**:
   - コミット処理はスキップし、ステップ 3 へ進みます。
3. **未コミットの変更が存在する場合**:
   - まず、変更内容に機密情報（`.env`、認証情報、秘密鍵など）や明らかに不要な一時ファイルが含まれていないか確認します。含まれる場合はそれらを除き、対象の変更をステージング（`git add`）します（すでにステージ済みの変更のみである場合はそのまま進めます）。
   - **`commit-message-generator` スキル**（`skills/commit-message-generator/SKILL.md`）の手順と規約に従って、`git diff --staged` およびプロジェクト内の仕様書・規約ドキュメントを参照し、Conventional Commits（またはプロジェクト規約）に沿った日本語のコミットメッセージを生成します。
   - **重要（確認の省略）**: `commit-message-generator` スキル単体ではコミット前にユーザー確認を求めますが、本スキル（`pr-creator`）のワークフローでは**ユーザーへの確認を行わず**、生成したメッセージでそのまま `git commit -m "<生成したメッセージ>"` を実行してください。

### 3. 分岐元（ベース）ブランチの特定
PR のターゲットとなるベースブランチには、**現在のブランチが分岐された元のブランチ**を指定します。以下の優先順位で分岐元ブランチを特定してください。

1. **reflog による確認**:
   - `git reflog show --no-abbrev <現在のブランチ>` の作成元履歴（`branch: Created from <分岐元>`）が残っていれば参照します。
2. **マージベースとコミット距離による特定**:
   - reflog から特定できない場合、リモート追跡ブランチを含む他の候補ブランチ（例: `git for-each-ref --format='%(refname:short)' refs/remotes/origin/ refs/heads/` から現在ブランチ・`origin/HEAD` 等を除外したもの）を対象に、`git merge-base HEAD <候補>` と `git rev-list --count <merge-base>..HEAD` を比較します。
   - 現在ブランチとの共通祖先から `HEAD` までのコミット数が最小となり、かつ現在ブランチがそのブランチから分岐したと判断できるブランチを分岐元とみなします。
3. **リモート存在確認とフォールバック**:
   - PR のベースブランチはリモートリポジトリ上に存在する必要があるため、特定したブランチがリモート（`origin/<ベースブランチ>`）に存在することを確認します。
   - ローカルのみに存在するブランチから分岐していた場合など、リモートに対応するブランチが見つからない場合は、さらにその親ブランチ、またはリポジトリのデフォルトブランチ（`gh repo view --json defaultBranchRef -q .defaultBranchRef.name` 等）をベースブランチとして選択します。

### 4. リモートへのプッシュ確認・実行
1. 現在のブランチがすでにリモートへプッシュされているか、またローカルに未プッシュのコミットがないかを確認します。
   - `git rev-parse --abbrev-ref --symbolic-full-name @{u}` で上流ブランチ（upstream）の有無を確認し、存在する場合は `git rev-list --count @{u}..HEAD`（未プッシュコミット数）および `git rev-list --count HEAD..@{u}`（リモート側のみのコミット数）を確認します。
2. **プッシュ済み（上流ブランチが存在し、未プッシュコミット数が 0 かつリモートと分岐していない）の場合**:
   - プッシュはスキップしてステップ 5 へ進みます。
3. **未プッシュのブランチ、または未プッシュのコミットがある場合**:
   - リモート側と履歴が分岐している（`HEAD..@{u}` が 1 以上ある）場合は、強制プッシュ（`--force`）は絶対に行わず、処理を中断してユーザーに報告してください。
   - 分岐していなければ、**ユーザーへの確認なしで** `git push -u origin <現在のブランチ>`（上流設定済みの場合は `git push`）を実行します。
4. プッシュ後、ベースブランチとの差分コミットが存在すること（`git rev-list --count <ベースブランチ>..HEAD` が 1 以上であること）を確認します。差分コミットが 0 件の場合は PR を作成できないため、その旨を報告して終了してください。

### 5. 変更内容の読み取りと PR タイトル・本文の生成
1. 特定したベースブランチと現在ブランチ間の変更内容をすべて読み取ります。
   - コミット一覧の確認: `git log <ベースブランチ>..HEAD --oneline`（必要に応じて詳細メッセージも確認）
   - 変更差分の確認: `git diff <ベースブランチ>..HEAD --stat` および `git diff <ベースブランチ>..HEAD`
   - 必要に応じてプロジェクト内の関連ドキュメント（Spec Kit の `specs/*/spec.md`、`plan.md`、`tasks.md`、Kiro の `.kiro/specs/*/`、OpenSpec の `openspec/` 等）も参照し、変更の背景や目的を正確に把握します。
2. **プロジェクト固有ルールの確認**:
   - リポジトリ内に PR テンプレート（`.github/pull_request_template.md`、`.github/PULL_REQUEST_TEMPLATE.md`、`.github/PULL_REQUEST_TEMPLATE/*.md` 等）や、コントリビューション規約・プロジェクトルール（`CONTRIBUTING.md`、`AGENTS.md`、`CLAUDE.md`、`.specify/memory/constitution.md` 等）が存在する場合は、そのフォーマット・記載項目・言語規約・タイトル規約に必ず従ってください。
3. **デフォルトの生成ルール（プロジェクト固有の言語・フォーマット指定がない場合）**:
   - PR のタイトルと本文は **日本語** で作成します。
   - タイトルは変更全体の要約を簡潔かつ明確に記述します（プロジェクトで Conventional Commits 風タイトル等が使われている場合はそれに合わせます）。
   - 本文には以下を含め、読み手（レビュアー）が変更内容を即座に把握できるように構成します。
     - **概要**: この PR の目的・解決する課題
     - **主な変更内容**: 変更ファイルや機能単位の箇条書き
     - **補足・確認事項**（該当がある場合）: 仕様書や関連 Issue 番号、テスト・ビルドの確認状況など

### 6. プルリクエストの作成と結果報告
1. GitHub MCP ツール、または `gh pr create` コマンドを用いて PR を作成します。
   - **確認なし**: ユーザーへの事前確認は行わず、そのまま作成を実行します。
   - **通常 PR**: Draft PR（`--draft`）にはせず、通常の PR として作成します。
   - **ベースブランチ指定**: ステップ 3 で特定した分岐元ブランチを明示的に指定します（例: `gh pr create --base "<分岐元ブランチ>" --head "<現在のブランチ>" --title "<タイトル>" --body "<本文>"`）。
2. PR 作成完了後、以下の情報をユーザーに報告します。
   - 作業ブランチ名と指定したベースブランチ名
   - 実施した操作（自動コミットの有無とコミットメッセージ、プッシュ実行の有無）
   - 作成した PR のタイトルと URL

## 厳守事項

- **`main` / `master` ブランチでの実行禁止**: 現在のブランチが `main` または `master` である場合は、コミット・プッシュ・PR 作成のいずれも一切実行せず、直ちに処理を中断してください。
- **ユーザー確認の省略**: ユーザーへの確認（コミット前、プッシュ前、PR 作成前）は求めず、自動的に一連の処理を完結させてください。
- **通常 PR としての作成**: 明示的な指示がない限り Draft PR にはせず、通常の PR として作成してください。
- **分岐元をベースに指定**: 安易にデフォルトブランチ決め打ちにせず、現在のブランチがどのブランチから切られたかを確認したうえでベースブランチを指定してください。
- **破壊的な Git 操作の禁止**: 強制プッシュ（`git push --force` / `-f`）、履歴の書き換え（`git rebase`、`git reset --hard`）、PR の自動マージは絶対に行わないでください。
- **事実に基づく記述**: PR 本文や最終報告には、実際にコミット・変更差分から読み取った事実のみを記載し、実行していないテストや確認事項を「実施済み」のように記載しないでください。
