# 仕様生成スキル

このスキルは、現在のプロジェクトのコミット履歴を分析し、プロジェクトに適した仕様書をマークダウン形式で自動生成・更新するためのものです。Spec Kit をはじめとする仕様駆動開発（SDD: Spec-Driven Development）フレームワークにも対応しています。エージェントは以下の手順で動作します。

## 対象となる仕様書・フレームワークの確認基準

仕様書の場所を特定する際は、単一ファイルだけでなく、プロジェクト内で仕様駆動開発フレームワークが使用されているかを優先的に確認してください。

- **Spec Kit (`spec-kit`)**: `.specify/` や `specs/` が存在する場合、`specs/<NNN-feature-name>/spec.md`（および必要に応じて `plan.md`、`data-model.md`、`.specify/memory/constitution.md`、`.specify/templates/`）を確認します。
- **Kiro / `cc-sdd`**: `.kiro/` が存在する場合、`.kiro/specs/<機能名>/requirements.md`（および `design.md`、`.kiro/steering/product.md` など）を確認します。
- **OpenSpec**: `openspec/` が存在する場合、`openspec/specs/` 配下の仕様書（および `openspec/changes/` 配下の変更提案）を確認します。
- **その他の仕様駆動開発フレームワーク**: プロジェクト内に導入されているフレームワーク固有の仕様ディレクトリ・テンプレートを確認します。
- **一般的な仕様書構成**: 上記フレームワークが使用されていない場合は、`SPEC.md`、`docs/spec.md`、`docs/specs/` などを確認します。

## 手順

1. まず上記の確認基準に従って、プロジェクト内の仕様書または仕様駆動開発フレームワークの構成を特定します。
   - 機能単位で複数の仕様ディレクトリが存在し対象が特定できない場合や、仕様書の配置場所が不明な場合はユーザーに確認してください。
2. 対象の仕様書が存在しない場合は、新規に作成するかどうかユーザーに確認してください。
   - 仕様駆動開発フレームワークが導入されている場合は、単一の `SPEC.md` 等を別途作るのではなく、そのフレームワークのディレクトリ構成・テンプレート（例: Spec Kit の `.specify/templates/spec-template.md` 等）に従って作成先と構成を提案してください。
3. 新規作成する場合は、プロジェクト（または対象機能）のコミット履歴を分析して、目的、機能要件、使用方法などを含む仕様を各フレームワークのフォーマット（未導入の場合は標準的なマークダウン形式）で生成してください。
4. 既に仕様書が存在する場合は、下記の手順で差分を追跡し、必要に応じて更新してください。
   - `git log -1 <仕様書のパス>` を実行して、対象の仕様書が最後に更新されたコミットを特定します。
   - `git log <最後の更新コミット>..HEAD` を実行して、仕様書の最後の更新以降のコミット履歴を取得します。
   - コミット履歴を分析して、既存の仕様書の内容（および各フレームワークのフォーマット規約）と照らし合わせます。
   - 仕様書に記載されていない新しい機能や変更点があれば、既存の構造や記述スタイル（ユーザーストーリーや EARS 記法など）を維持したまま仕様書に追加してください。
5. 仕様書の内容を生成・更新した場合は、ユーザーに変更内容を説明してください。

## 厳守事項

- コミット履歴の取得（`git log` など読み取り系コマンド）以外の Git 操作はこのスキルの範囲外です。
- `git add` や `git commit` などのコマンドは実行しないでください。仕様書の内容を変更する際は、ユーザーに提案し、確認を得るかユーザーが手動で変更を加えることを推奨してください。
